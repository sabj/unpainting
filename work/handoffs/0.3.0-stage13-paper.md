# Stage 13: incremental paper observation

The current client is `src/media/gpu/link.mjs` (not `src/gpu/client.mjs`).

## Caller and synchronization audit

- `tools/paint-plate.mjs` routes observations through `measurePaper`,
  `measurePaperBatch`, and `measurePaperDry` in `src/paint/methods/wetdry.mjs`.
  Value-plan admission, own-wash gates, prewet preparation, and wet-bed waits
  already request `stats: 'gate'` in Fast mode. Semantic/major-area command
  evidence, preparation, film admission/removal, and checkpoint observations
  also use these methods. They retain their existing statistics and decisions.
- In this checkout the gate result is `waterMax`, `saturationMax`, `moistShare`,
  and `dry`; it does not have a `waterSum` field. Arbitrary cell-set membership
  and the original denominator are preserved by the new gate path.
- `measurePaper` first checks the exact-zero and wet-reach certificates, then
  requests fresh W/s/M over the remaining footprint. Batch measurement shares
  one observation when a certificate cannot narrow individual groups.
- `GpuLink.ensurePaperFresh` falls back to full `ensureFresh` when paper-only
  observation is disabled, during CPU strokes/demand windows, or while paused.
  It flushes queued dry metadata, uploads authoritative host writes, and keeps
  paper freshness separate from pigment freshness. Full `ensureFresh` still
  synchronizes the newest layer and marks paper tiles only for a matching epoch.
- Both `worker.mjs` and `batch-server.mjs` receive `paperDown`. Their paths now
  call `GpuSheet.readPaperRects`; `readPaperRect` remains a single-region wrapper.
  The standalone worker drains preceding steps and the packer flushes strokes.
  The packed response still uses the existing shared mailbox and ACK ordering.

## Implementation

- Exact synchronous dry completion clears host W/s/M and establishes a fresh
  paper cache independently of pigment and layer state. A queued dry establishes
  a pending cache; subsequent strokes invalidate their contact/lift rectangles,
  and flow expands the conservative wet bound by three cells per step, matching
  the existing wet-reach certificate. The worker confirms exact zero when dry
  metadata is drained before observations use the cache. Threshold-only dry
  completion, untracked mutations, and host writes fall back conservatively.
- The dry queue's automatic capacity drain resolves the pending cache too.
  Metadata draining never treats an earlier dry as the state after a later
  stroke: later contact and flow tiles remain stale.
- `FreshMap.staleRects` returns disjoint dirty tile runs, including clipped edge
  tiles. It retains the existing 64-cell lookahead only for dirty tiles; a fresh
  requested region never triggers a read of unrelated lookahead tiles. Fresh
  gaps between stale regions are excluded from the transfer.
- `paper-readback.mjs` packs only W/s/M from all dirty runs in one compute
  dispatch and one `mapAsync`, with exact f32 values and numeric M conversion.
  The old packer also packed EVER and every G/P/D pigment plane before copying
  its W/s/M prefix. The new packer binds five storage buffers and reuses its
  descriptor, packed, and readback allocations. It never changes simulator
  fields or gate thresholds. No f16 approximation or image-specific rule is used.

## Validation and benchmark

Gate-only observations of at least 256 cells can use `paper-gate.mjs` instead
of refreshing CPU arrays. One workgroup reduces each 256 selected indices into
32 bytes. The host combines maxima and moist counts and normalizes the winning
cell's original S/capacity in double precision. The GPU also computes partial
water sums, but these are not added to the existing public result schema.
Wet-reach filtering excludes certified-zero cells while retaining the original
cell count as the moist-share denominator. A four-entry cache compares actual
index contents and simulation versions, including mutable or duplicated sets.
GPU gate results never mark pigment or paper arrays coherent.

Water's moist comparison uses the first f32 at or above the JS threshold.
Saturation values within 1e-6 of the dry/moist thresholds, or a maximum
within 1e-6 of the prewet-depth threshold 0.5, use the exact CPU observation
path. Subnormal water/pore values and capacities below the normalization floor
also fall back; reduced arithmetic cannot establish a false exact-zero proof. The reported saturation maximum can differ in its last bits
when multiple normalized values round to the same GPU f32; the gate's boundary
fallback protects admission decisions. No dry/moist threshold is relaxed.

Validation: `npm test` passed 1,438 tests, with 2 skips and no failures;
`npm run bench:test` passed all 83. The final logs are `npm-test-guarded.log`
and `bench-test-guarded.log`. Real GPU tests compare complete W/S/M arrays
against full readbacks after local strokes, separated contacts, flow, queued
and synchronous dry, threshold-only dry with residual moisture, host uploads,
and automatic queue draining. Gate tests cover selected/duplicated/mutable
indices, cache reuse, wet-reach filtering, and precision fallbacks.
The Lab synchronization check passes; no generated Lab files change.

There were no precision fallbacks in these measured workload runs. Net transfer

**The requested large reduction in total observation waits was not achieved.**
The operation named paperDown largely disappears, but its synchronization moves
to paperGate. These timers include preceding queued GPU work, not just mapped
buffer transfer. The number of synchronization points does not fall; a few full
observations following gate-only observations add reads because reductions do
not populate CPU arrays. Overall warm wall time is essentially unchanged in
these single samples. This is a transfer-volume optimization, not a material
end-to-end speedup. Further wait reduction requires moving admission decisions
and dependent work onto the GPU, rather than only reducing the returned data.

**The requested SSIM >= 0.99 gate passes general and ink, but fails value-plan.**
Value-plan is 0.98750909 both before and after this change. Its unchanged SHA-256
`ee47b87bf09e466756a28757aabe48e6f830640c47bf12ebb5ede5524cc66f69` is already
recorded in the Stage-7 and Stage-8 handoffs. The readback changes introduce no
pixel regression, but do not repair that existing quality shortfall. The
`quality.py` check intentionally exits 1 for this failed control threshold;
it is not reported as a passing quality gate.

The value-plan run's accepted exit 3 is the frozen workload's existing unused
`--skylanes --skylanemm --skylanestep` flags, not a GPU or paint-check failure.

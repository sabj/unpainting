### Measured priority for Stages 4 and 5

- **O1/O3 paper measurement and synchronization:** 24.59 s / 127.09 s / 8.70 s on inkres/valueplan/general: 14.0% / 28.0% / 10.3% of wall time. Ideal elimination ceilings are 1.16× / 1.39× / 1.11×. These timers include queued GPU dry waits, so preserving drying lowers the realizable savings.
- **M3/O16 layer memory:** distinct coarse-layer backing allocations are 1.99 GB / 11.85 GB / 0.239 GB. The valueplan is the strongest memory stress case. Shared empty planes already save substantial memory; counting all plane references would falsely report 103.9 GB for it. Reader-safe changes still need exact parity.
- **M2 thickness materialization:** `thicknessCached` accounts for 35.22 s of exclusive main-thread samples on valueplan (7.8% of end-to-end wall). This is sampled attribution, not a separately timed total for the whole optimization.
- **M1 composition:** inkres compose takes 6.52 s (3.7%, ideal ceiling 1.039×); prioritize only as a modest measured component. Isolated carry takes 1.36 s (0.77%, ceiling 1.008×), so demote carry-only work. This does not bound every effect of single-pigment specialization.
- **Demote encoder parallelism:** measured encode/write awaits are 0.49% / 0.11% / 0.28%; even removing them entirely cannot exceed 1.005× here. This says nothing about Class C baseline reuse.
- JSONL volume and Dijkstra counts establish workload sizes, not time shares. Keep JSON serialization, pen-buffer setup, and line preprocessing unranked until their attributed spans justify a factor; do not multiply overlapping ceilings or infer a speedup from these single observations.

## Interpretation and gates

Phase ceilings are disjoint approximations rounded to 0.1 seconds. The named drawing span includes opening pen execution inside the painting phase; WALL_PHASES drawing alone is not total pen time. Operation timers are nested inside phases and must not be added to them or to gpuStats. The observed fast dry chunk is read from dryTelemetry.fastChunk (50 on this baseline); do not assume the optional 200-step setting was active. measurePaper timing includes draining queued dry work, so eliminating that whole interval is an optimistic bound: exact gates must still preserve drying. A sink below 2% cannot justify priority on this workload: even perfect removal is below 1.021×. Bytes and call counts alone do not establish time share; do not demote unmeasured JSON serialization, pen setup, or layer readers based on them. CPU samples guide attribution but are not exact operation timers. No multiplied speedup claim is supported.

First-mark timing includes calibration/scrap calls. Pen counters count the physical dip-pen implementation; graphite marks do not increment them. Final layer counters count allocated CPU planes and test their current CPU contents; deferred-archive bytes and readback counters in backend.json are the authoritative GPU evidence. Dry stack counts distinguish calibration, shape gates, pass boundaries and pen calls without changing their execution. Missing GPU telemetry fields are unsupported, not measured zeros.

Experiment 7 commands and mandatory Stage 4/5 gate are in [parity/README.md](../../src/media/parity/README.md). CPU compares to frozen CPU and GPU to frozen GPU on the same adapter; cross-backend equality is not assumed. The merged baseline establishes future exactness, not historical pre-switch correctness. The fused wet-scan kernel requires 13 storage bindings; where capabilities.fusedWetScan is false on this adapter it is SKIPPED, not passed. The separate wet-scan path is covered. The full 13-target 540px release sweep remains required beyond these fixtures.

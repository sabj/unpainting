# V4 and V5 inputs

In V4 and V5 the model does not paint stroke by stroke. It writes a plan for the painter (`tools/paint-plate.mjs`): regions, reserves, styles, drawing paths, recipe tokens and painter settings. Then it paints the plan with `bench/paint.sh`. The painter stops at every passage boundary, so the model can look at its sheet and revise what is not painted yet. [scripts/pipeline/round45.mjs](../scripts/pipeline/round45.mjs) runs a round.

- Two plan forms (`npm run bench:run -- ... --planform token|area`). **token** (the default, and the route every stored plan and baseline used): `config.json`, recipe tokens over the base `region_w13_lay4_sky3_skyb_cpp` and painter settings. **area**: one area plan, `bench/plan/area-plan.json` (the contract of `tools/painter/semantic-areas.mjs`), with its drawing section (`drawing` {medium, reason, ink?}, `paints`, each area's `drawingRole`, and opening/closing line files). The area route has no tokens, no base recipe and no forced painter settings; the harness keeps the template, the target guard, strict mode, the subject-medium rule, the line-file limits and the refusal of gains (`load.pigmentScale` must be 1). Its brief is [TASK-area.md](TASK-area.md), its check [scripts/pipeline/area-check.mjs](../scripts/pipeline/area-check.mjs) (the painter's planning step with `--areaplanonly 1` at full width, and an area map), its worked example [example-area/](example-area/). An area plan stops at every pass boundary for looks, but cannot be revised once painting has started (the painter does not carry an area plan's state across a re-plan). Example plans in the repository named after a benchmark subject leave the model's tree on the area route. `--skills <dir>` seeds another skills folder (for example one written for area plans).
- [TASK.md](TASK.md): the brief. [round-V4.md](round-V4.md), [round-V5-first.md](round-V5-first.md) and [round-V5-next.md](round-V5-next.md) fill its round rules; [feedback-section.md](feedback-section.md) is added from V5 try 2.
- [TOKENS.md](TOKENS.md): the recipe tokens and the painter settings each sets, generated by [scripts/pipeline/tokens.mjs](../scripts/pipeline/tokens.mjs).
- [PAINT.md](PAINT.md), [paint.sh](paint.sh) and [paint.mjs](paint.mjs): the model's paint commands. Each is a request file the harness answers.
- [check.sh](check.sh): the admission check, which runs [scripts/pipeline/check.mjs](../scripts/pipeline/check.mjs).
- [subjects.json](subjects.json): the painting width, sheet size, requested style and drawing medium (`medium`: `pen`, `pencil` or `none`, as seen in the target) of each target.
- [tools/](tools/): the two line tracers the brief offers.
- [example/](example/): a worked, admitted plan for a synthetic seascape that is not a benchmark target.

Rules:

- One target per session, one session per try. The model has 85 minutes of its own time. Time it waits in `bench/paint.sh` is not counted.
- Looks are stepping back, not search: three looks while painting, at stops the model chooses, and one at the finished painting. A revision follows a look, once, at that stop. By default a look shows the target beside the sheet. A strict run (`--notargetlooks 1`) shows the sheet only and removes `bench/plan/target.png` from the worktree when painting starts, so the model has no target view after planning. Every answer the model reads is kept in the try's `paint-answers.jsonl`. The target guard stays on in the painter.
- A finished painting counts. A setting the plan asks for that the painter never reads, an option nobody asked for and a passage with no brush path are recorded in the try's `pipeline.notes` and `optionCheck`, not failed. `npm run bench:run -- ... --strict-verdict` fails the painting on them instead, as the published 0.1 results did; use it when comparing with those. A painter killed by a signal, any other painter exit than 0 or 3, and no finished painting still fail.
- Every subject gets the same base recipe and template; no token or paint box applies to one subject. The plan picks its pigments with `--paints`.
- If the session ends without a painting, the harness checks the plan and paints it without stops. A missing or refused plan gets one repair turn in the same session. So does a plan the painter refuses at full size.
- The pigments cannot change once painting has started.
- Ink follows the subject's medium, whether or not the plan asks. On a subject whose `medium` is not `pen`, any drawing (ink from `drawing.medium`, `--outlinemedium ink` or `auto`, graphite, or a plan that says nothing) has its opening lines drawn in graphite before the washes; its closing lines and pen-only settings are dropped. The check prints the override as `layering.mediumOverride`, and the try records it as `pipeline.mediumOverride`. On a `pen` subject a plan that names no medium is drawn in ink, opening and closing lines; a plan that names a medium, or draws nothing, is run as written.
- V5 tries after the first get `bench/feedback/`: the previous try's painting, plan, stops and the judges' words. No score, metric or judge number goes back to the model between tries. The model is asked to write `bench/SELF-REVIEW.md` before it reads the judges. The order is asked for, not enforced.
